# KeysDock Hardware Architecture

## Scope

This document describes the current hardware revision only.

- The source of truth is the KiCad design data under `hardware/` and the local datasheets under `hardware/docs/`.
- Firmware and software in this repository are still demo-stage and are not used here as architectural source material.
- `suitekits/` is mechanical content and is excluded from this review.
- The battery pack now assumed for the portable version is `ATL3237115`, `2450 mAh`, with a `0.5C` target charge current and a vendor-reported `2 A` maximum discharge current.
- The battery vendor explicitly allows charging this pack to `4.2 V` to improve cycle life, so the present `BQ24074` charge-voltage choice is treated as intentional.
- The charger `TS` pin is intentionally fixed with a resistor because this product version does not route a pack NTC.
- The net name `P,+5` is kept as the existing high-voltage / LED-supply naming convention. It should not be interpreted as a guaranteed regulated 5 V rail.

## System Partition

KeysDock is partitioned into one active controller board, one main sensing board, one optional sensing expansion, and one passive interposer.

- The controller board owns USB, battery interface, charge/power-path management, the `P,+3.3` buck rail, the ESP32-C6, the external SPI ADC, and the encoder.
- The typeboard owns the main 64-key hall matrix and the bulk of the RGB chain.
- The external board is a hall-only analog dock that adds 14 more keys.
- The connector board only bridges the 20-pin mezzanine between controller and typeboard.

## Power Architecture

### Rail Tree

The observed rail tree is:

`USB-C VBUS -> USB_PWR_SUPP -> U2 BQ24074 -> P,+ -> U6 TPS62142 -> P,+3.3`

- `P,+` is the charger `OUT` rail. It is the shared system rail and the LED supply rail.
- With valid external input present, `BQ24074` regulates `OUT` to about `4.4 V` typ.
- Without external input, `P,+` falls back toward the battery voltage through the power-path FET.
- `P,+3.3` is the fixed logic / sensor rail generated by `TPS62142`.

### Battery Pack and Charge Policy

The portable version is now assumed to use `ATL3237115`.

- Capacity: `2450 mAh`
- Target charge current: `0.5C ~= 1.225 A`
- Vendor-reported maximum discharge current: `2 A`
- Vendor guidance: charging to `4.2 V` is allowed and preferred for longer service life

The current `BQ24074` programming on the controller board is:

| Function | Installed network | Resulting behavior |
| --- | --- | --- |
| `ISET` | `R7 = 750 ohm` | `ICHG_typ ~= 890 / 750 ~= 1.19 A` |
| `ILIM` | `R8 = 1.10k`, with `EN2 = High`, `EN1 = Low` | `IINMAX_typ ~= 1610 / 1100 ~= 1.46 A` |
| `ITERM` | `R11 = 3k` | `ITERM_typ ~= 0.03 x 3000 / 750 ~= 120 mA` |
| `TS` | `R1 = 10k` to ground | fixed no-NTC bias |
| `TMR` | floating | default safety timers |
| `~CE` | hard low | charging enabled unless faulted |

This means the present charge-current setting is already close to the pack's `0.5C` target. The remaining power-path concern is not the battery charge current itself, but the USB input-source assumption used to allow that current.

### USB-C Front End and Source Assumptions

The controller board implements the basic sink and ESD network correctly.

- `CC1` uses `R4 = 5.1k` to `P,E`.
- `CC2` uses `R2 = 5.1k` to `P,E`.
- `U4 = TPD4E05U06DQAR` protects `CC1`, `CC2`, `USB_D+`, and `USB_D-`.
- `D2 = TPD1E10B06DPYR` protects `USB_PWR_SUPP`.

However, the current board does not include:

- CC voltage sensing,
- BC1.2 source classification,
- USB PD negotiation, or
- a hardware path that changes the charger mode based on the detected source type.

At the same time, the charger is not left in `USB100` or `USB500` mode. It is hard-configured into the resistor-programmed `ILIM` mode through `EN2 = High`, `EN1 = Low`, and `R8 = 1.10k`.

Architecturally, this means the current controller behaves like an adapter-oriented sink, not a host-aware USB peripheral. For a battery-powered keyboard that may plug directly into a PC host port, this remains the most important power-path boundary of the current design.

### Charger Status Signals

The charger status outputs are now electrically safe for the MCU.

- `BAT_PGOOD` is routed to `ESP32-C6 GPIO4` and pulled up to `P,+3.3` by `R25 = 1.5k`.
- `BAT_CHG` is routed to `ESP32-C6 GPIO5` and pulled up to `P,+3.3` by `R17 = 1.5k`.

This fixes the earlier voltage-domain problem. The remaining caveat is functional rather than electrical: `GPIO4` and `GPIO5` are still boot-related pins (`MTMS` / `MTDI`), so reset behavior should be validated under all charger states.

### 3.3 V Generation

`U6 = TPS62142` is the fixed `3.3 V` member of the `TPS6214x` family.

- `L1 = 2.2 uH`
- `C8 = 10 uF` on the input rail
- `C10 = 22 uF` on the output rail
- `C9 = 3.3 nF` on `SS/TR`

The component values are broadly aligned with the TI application guidance for a `3.3 V` rail. The important remaining caveat is layout and grounding: the current board splits `AGND`, `PGND`, and exposed-pad return domains across `P,GND` and `P,E`, which is less direct than TI's recommended common-ground implementation.

## Hall-Sensor and ADC Architecture

### Main Board Scan Path

The main typeboard uses four identical `keys-group` sub-sheets.

- Each sheet contains 16 `SC4823S6-TR` linear hall sensors.
- Each 16-sensor group feeds one `XL4067TS` analog multiplexer.
- The four group outputs are exported as `KEYS_DT_1` through `KEYS_DT_4`.

### External Dock Scan Path

The external dock contributes the fifth analog return path.

- 14 `SC4823S6-TR` sensors feed one `XL4067TS`.
- The dock exports its mux output as `KEYS_ADC_OUT`.
- That signal crosses the 8-pin pogo link to the typeboard and then continues to the controller as `KEYS_DT_5`.

### Controller-Side Acquisition

The controller digitizes the five scan returns with `U3 = TLA2518`.

- `AIN2..AIN6` are assigned to `KEYS_DT_1..5`.
- `AIN7` is used for battery telemetry through a divider:
  - `R20 = 100k` from `VBAT` to `AIN7`
  - `R21 = 100k` from `AIN7` to `P,GND`
  - `C13 = 100 nF` from `AIN7` to `P,GND`
- `AVDD` and `DVDD` are tied to `P,+3.3`.
- Local ADC support capacitors are present:
  - `C2 = 1 uF` on `AVDD`
  - `C11 = 1 uF` on `DVDD`
  - `C3 = 1 uF` on `DECAP`

The divider keeps the battery sense voltage inside the ADC range. Because the divider's Thevenin impedance is `50k`, `AIN7` should be treated as a slow housekeeping channel rather than part of the highest-rate key scan loop.

### Electrical Compatibility of the Scan Chain

The selected parts are electrically compatible for a `3.3 V` ratiometric hall-keyboard front end.

- `SC4823S6-TR` operates from `2.5 V` to `5.5 V` and draws about `0.6 mA` active current.
- `XL4067TS` operates from `2 V` to `10 V`.
- `TLA2518` accepts `0 V` to `AVDD` single-ended inputs and uses `AVDD` as its reference.

In the current population, the design uses 78 active hall channels across 80 available scan slots (`16 addresses x 5 analog returns`).

## Low-Power Hall Hooks

The main typeboard includes real sleep / wake wiring for the hall sensors.

- `RANA` is the shared hall `SLEEP` control bus.
- `SAKI_MOVE` is the shared hall `AWAKE` bus from the main 64-key board.
- On the controller board:
  - `R19 = 100k` pulls `RANA` low to `P,E`
  - `R18 = 10k` pulls `SAKI_MOVE` high to `P,+3.3`
- `SAKI_MOVE` lands on `ESP32-C6 GPIO3`, which is in the LP domain.
- `RANA` lands on `ESP32-C6 GPIO21`.

This is meaningful because the `SC4823` supports:

- active mode with `SLEEP = 0`,
- deep sensor sleep with microamp current when `SLEEP = 1`, and
- a wake-detect mode where the device checks for a large output shift at about `12.5 ms` intervals and asserts `AWAKE` low.

The external dock is intentionally asymmetric.

- `HE_SLEEP` is strapped low locally, so the dock is always in active scan mode.
- `HE_AWAKE` remains local to the dock.
- No dock wake / status line returns to the controller through the pogo link.

## Lighting Architecture

The RGB chain is split across two boards.

- The typeboard carries 65 LED footprints.
- The controller board carries one local RGB LED before the `TOMO0` chain output.
- Total system RGB count is 66 devices.

The LED supply rail is `P,+`, which is the charger/system rail described earlier.

Important consequences of the current architecture:

- The typeboard does not currently show explicit `P,+` bulk capacitance; its clear top-level bulk capacitors (`C13`, `C14`) are on `P,+3.3`.
- The battery pack is vendor-limited to `2 A` maximum discharge current.
- A full-white worst-case current estimate for 66 WS2812-class RGB devices exceeds what should be assumed safe for battery-only operation, for the charger power-path, and for the mezzanine contacts without validation.

As a result, RGB current limiting is part of the system architecture, not just firmware polish. The final brightness ceiling and source-aware derating policy still need to be validated.

## Interconnects

### Controller to Typeboard: 20-Pin Mezzanine

The controller-to-typeboard link carries the complete keyboard interface.

- Power and return:
  - `2 x P,+`
  - `2 x P,+3.3`
  - `3 x shared return`
- Shared mux control:
  - `KEYS_CH_A`
  - `KEYS_CH_B`
  - `KEYS_CH_C`
  - `KEYS_CH_D`
  - `KEYS_CH_CE`
- Analog returns:
  - `KEYS_DT_1`
  - `KEYS_DT_2`
  - `KEYS_DT_3`
  - `KEYS_DT_4`
  - `KEYS_DT_5`
- Sideband:
  - `TOMO0`
  - `RANA`
  - `SAKI_MOVE`

The link is implemented with the Panasonic P5KF family (`AXK5` / `AXK6`) and a passive interposer board.

- The connector family is rated for `0.5 A` per pin contact and `10 A` total across contacts.
- The interposer is passive-only.
- Current routed `P,+` segments on the interposer are `0.8 mm` to `1.0 mm` wide with supporting copper pours.

Because the LED rail is carried over this mezzanine, this interconnect must be treated as part of the power-distribution design, not as a logic-only link.

### Typeboard to External Dock: 8-Pin Pogo Link

The dock interface carries:

- `KEYS_CH_A`
- `KEYS_CH_B`
- `KEYS_CH_C`
- `KEYS_CH_D`
- `KEYS_CH_CE`
- `KEYS_ADC_OUT`
- `P,+3.3`
- return

No RGB rail and no sleep / wake sideband are carried on the pogo link.

## Grounding and Return Strategy

The active boards still do not use one simple continuous ground net.

- Controller:
  - `P,E` and `P,GND` are both used
  - `R10` bridges them
  - `TLA2518` signal ground pin uses `P,GND`, while its exposed pad uses `P,E`
  - `TPS62142` `AGND` uses `P,GND`, while `PGND` and the exposed pad use `P,E`
- Typeboard:
  - `P,E` and `P,GND` are both used
  - `R1` bridges them
  - repeated key-group circuitry returns locally through `P,E`
  - top-level bulk capacitors `C13` and `C14` return through `P,GND`
- External dock:
  - `P,E` and `P,GND` are both used
  - `R4` bridges them
  - hall circuitry and local decoupling return through `P,GND`
  - the pogo return pin is mapped as `P,E`

This means the split ground scheme is not preserved end-to-end across the system. It remains the main mixed-signal integrity risk in the current design.

## PCB Implementation Snapshot

### Common Stackup

The reviewed active boards use a 4-layer, `1.2 mm` stackup.

- `F.Cu`
- `In1.Cu`
- `In2.Cu`
- `B.Cu`

### Local Decoupling as Placed in the Current PCB Files

- Controller board:
  - local USB, charger, buck, and ADC capacitors are present
- Typeboard:
  - each `keys-group` includes local `P,+3.3` decoupling
  - additional `C13 = 22 uF` and `C14 = 22 uF` are placed on `P,+3.3`
- External board:
  - `C1 = 100 nF`, `C2 = 4.7 uF`, and `C3 = 10 uF` are present on `P,+3.3`

### Footprint Trend

Many of the high-value capacitors in the design use `0402` footprints, including `10 uF` and `22 uF` entries on the controller and sub-boards. Their effective capacitance under DC bias will be much lower than the printed nominal value.

## Current Design Boundaries

The current hardware is workable, but these boundaries should be treated as real and explicit:

- USB input-source classification is not implemented; the charger currently behaves like an adapter-oriented sink.
- The typeboard still lacks explicit `P,+` bulk capacitance close to the LED rail entry.
- The `P,E` / `P,GND` split remains across all active boards and is not applied consistently.
- `GPIO15 / KEYS_CH_C` still has no dedicated external bias on the controller board.
- The battery pack's `2 A` maximum discharge rating constrains the final RGB brightness policy and must be reflected in firmware current limiting.
