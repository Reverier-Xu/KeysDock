# KeysDock Hardware Architecture

## Scope

This document describes the current hardware only.

- Firmware and software in this repository are still demo-stage and are not used here as architectural source material.
- `suitekits/` is mechanical content and is excluded from this review.
- The source of truth is the KiCad design data under `hardware/` and the local component datasheets under `hardware/docs/`.

## Board Set

| Board | Role | Main devices | Notes |
| --- | --- | --- | --- |
| `hardware/controller.kicad_sch` / `hardware/controller.kicad_pcb` | Main controller, USB-C input, battery/power path, ADC front end | ESP32-C6-WROOM-1-N8, BQ24074, TPS62142, TLA2518, EC12 encoder | Also hosts the first RGB LED in the chain |
| `hardware/typeboard.kicad_sch` / `hardware/typeboard.kicad_pcb` | Main keyboard sensing and lighting board | 64 x SC4823S6-TR, 4 x XL4067TS, 65 x WS2812-compatible LEDs | Carries the pogo pass-through to the external dock |
| `hardware/external.kicad_sch` / `hardware/external.kicad_pcb` | External hall-sensor dock | 14 x SC4823S6-TR, 1 x XL4067TS | No RGB and no `P,+5` rail |
| `hardware/connector.kicad_sch` / `hardware/connector.kicad_pcb` | Passive controller-to-typeboard interposer | 2 x AXK5F20347YG | Purely mechanical/electrical bridge |
| `hardware/keys-group.kicad_sch` | Reusable 16-key hall/mux sub-sheet | 16 x SC4823S6-TR, 1 x XL4067TS, local 3.3 V decoupling | Instanced four times on the typeboard |
| `hardware/testpad.kicad_sch` / `hardware/testpad.kicad_pcb` | Bring-up breakout | breakout only | Optional lab accessory |

## System Partition

KeysDock is partitioned into one active controller board, one main sensing board, one optional sensing expansion, and one passive interposer.

- The controller board owns USB, battery interface, charge/power-path management, the 3.3 V buck rail, the ESP32-C6, the external SPI ADC, and the encoder.
- The typeboard owns the main 64-key hall matrix and the bulk of the RGB chain.
- The external board is a hall-only analog dock that adds 14 more keys.
- The connector board only bridges the 20-pin mezzanine between controller and typeboard.

## Power Architecture

### Rail tree

The observed rail tree is:

`USB-C VBUS -> USB_PWR_SUPP -> U2 BQ24074 -> P,+5 -> U6 TPS62142 -> P,+3.3`

- `P,+5` is the charger `OUT` rail, not raw USB VBUS and not a fixed 5 V regulator.
- With the BQ24074, `OUT` is nominally regulated near 4.4 V while valid input is present and falls back toward battery voltage when external input is absent.
- `P,+3.3` is the fixed logic/sensor rail generated by the TPS62142 buck converter.

### USB-C front end

The controller board already includes the basic USB-C sink and ESD network.

- CC1 uses `R4 = 5.1k` to `P,E`.
- CC2 uses `R2 = 5.1k` to `P,E`.
- `U4 = TPD4E05U06DQAR` protects `CC1`, `CC2`, `USB_D+`, and `USB_D-`.
- `D2 = TPD1E10B06DPYR` protects `USB_PWR_SUPP`.

### As-built BQ24074 configuration

The current controller PCB populates the charger as follows.

| Function | Installed network | Resulting as-built value |
| --- | --- | --- |
| `ISET` | `R7 = 1.78k` to `P,E` | about `500 mA` fast-charge current |
| `ILIM` | `R8 = 1.54k` to `P,E`, with `EN2 = High`, `EN1 = Low` | about `1.0 A` resistor-programmed input-current limit |
| `ITERM` | `R11 = 3k` to `P,E` | about `50 mA` termination current |
| `TMR` | floating | default safety timers |
| `TS` | `R1 = 10k` to `P,E` | fixed `TS` bias; no pack NTC is currently routed |
| `~CE` | hard low (`P,E`) | charging enabled when no fault blocks it |

Status outputs are also brought into the MCU.

- `BAT_PGOOD` is routed to `ESP32-C6 GPIO4` and pulled up by `R25 = 1.5k` to `P,+5`.
- `BAT_CHG` is routed to `ESP32-C6 GPIO5` and pulled up by `R17 = 1.5k` to `P,+5`.

### 3.3 V generation

`U6 = TPS62142` is the fixed 3.3 V member of the TPS6214x family.

- The controller PCB includes local power-stage capacitors around the buck:
  - `C8 = 10uF` on `P,+5`
  - `C10 = 22uF` on `P,+3.3`
  - `C9 = 3.3nF` on `SS/TR`
- The installed inductor is `L1 = 22uH`, rated `3.8 A`, with `55 mohm` DCR in the KiCad part data.
- The hall-sensor domain is light enough that the 3.3 V rail is not the system's dominant power problem; lighting and charge-path behavior are.

## Hall-Sensor and ADC Architecture

### Main board scan path

The main typeboard uses four identical `keys-group` sub-sheets.

- Each sheet contains 16 `SC4823S6-TR` linear hall sensors.
- Each 16-sensor group feeds one `XL4067TS` analog mux.
- The four group outputs are exported as `KEYS_DT_1` through `KEYS_DT_4`.

### External dock scan path

The external dock contributes the fifth analog return path.

- 14 `SC4823S6-TR` sensors feed one `XL4067TS`.
- The dock exports its mux output as `KEYS_ADC_OUT`.
- That signal crosses the 8-pin pogo interface to the typeboard and then continues to the controller as `KEYS_DT_5`.

### Controller-side acquisition

The controller board digitizes the five analog return lines with `U3 = TLA2518`.

- `AIN2..AIN6` are assigned to `KEYS_DT_1..5`.
- `AIN7` is used for battery telemetry through a divider:
  - `R20 = 100k` from `VBAT` to `AIN7`
  - `R21 = 100k` from `AIN7` to `P,GND`
  - `C13 = 100nF` from `AIN7` to `P,GND`
- `AVDD` and `DVDD` are both tied to `P,+3.3`.
- Local ADC support components are present on the controller board:
  - `C2 = 1uF` on `AVDD`
  - `C11 = 1uF` on `DVDD`
  - `C3 = 1uF` on `DECAP`

### Electrical compatibility of the scan chain

The selected parts are electrically compatible for a 3.3 V ratiometric hall keyboard.

- `SC4823S6-TR` operates from `2.5 V` to `5.5 V`, draws about `0.6 mA` active current, and has a typical zero-field output near `0.90 * VCC`.
- `XL4067TS` operates from `2 V` to `10 V`.
- `TLA2518` accepts `0 V` to `AVDD` single-ended inputs and uses `AVDD` as its ADC reference.

In the current design, the main keyboard exposes 78 populated hall channels across 80 scan slots (`16 addresses x 5 analog returns`).

## Low-Power Hall Hooks

The main typeboard includes shared sleep/wake wiring for the hall sensors.

- `RANA` is the shared hall `HE_SLEEP` control bus.
- `SAKI_MOVE` is the shared hall `HE_AWAKE` bus from the main 64-key board.
- On the controller board:
  - `R19 = 100k` pulls `RANA` down to `P,E`
  - `R18 = 10k` pulls `SAKI_MOVE` up to `P,+3.3`
- `SAKI_MOVE` lands on `ESP32-C6 GPIO3`, which is an LP-domain pin.
- `RANA` lands on `ESP32-C6 GPIO21`.

The external dock is intentionally different.

- `HE_SLEEP` is hard-tied low through `R5 = 100 ohm` to `P,E`.
- `HE_AWAKE` is pulled up through `R3 = 10k` to `P,+3.3`.
- No dock wake line returns to the controller through the pogo link.

## Lighting Architecture

The RGB chain is split across two boards.

- The typeboard carries 65 `XL-6028RGBW-WS2812B` footprints.
- The controller board carries one local RGB LED before the `TOMO0` output chain.
- Total system RGB count is 66 devices.
- The typeboard applies a `100 ohm` series resistor (`R2`) on `TOMO0`.

Important rail fact:

- The RGB supply is `P,+5`, which is the charger `OUT` rail described above.
- The typeboard has no capacitor footprint tied to `P,+5`; all of its explicit capacitor footprints are on `P,+3.3`.

## Interconnects

### Controller to typeboard: 20-pin mezzanine

The 20-pin board-to-board link carries the full controller-to-keyboard interface.

- Power and return:
  - `2 x P,+5`
  - `2 x P,+3.3`
  - `3 x shared return`
- Shared mux control:
  - `KEYS_CH_A`
  - `KEYS_CH_B`
  - `KEYS_CH_C`
  - `KEYS_CH_D`
  - `KEYS_CH_CE`
- Analog returns:
  - `KEYS_DT_1`
  - `KEYS_DT_2`
  - `KEYS_DT_3`
  - `KEYS_DT_4`
  - `KEYS_DT_5`
- Sideband:
  - `TOMO0`
  - `RANA`
  - `SAKI_MOVE`

The passive connector board bridges this link mechanically and electrically. On its PCB:

- all `P,+5` routed segments are `0.3 mm` wide,
- the one routed `P,+3.3` segment is `0.8 mm` wide,
- `P,+5` also uses copper zones on the interposer.

### Typeboard to external dock: 8-pin pogo link

The pogo interface is the minimum hall-only dock link.

- `KEYS_CH_A`
- `KEYS_CH_B`
- `KEYS_CH_C`
- `KEYS_CH_D`
- `KEYS_CH_CE`
- `KEYS_ADC_OUT`
- `P,+3.3`
- return

No RGB rail and no sleep/wake sideband are carried on the pogo link.

## Grounding and Return Strategy

The active boards do not use a single simple ground net.

- Controller:
  - `P,E` and `P,GND` are both used
  - `R10` bridges them
  - the ADC ground pins use `P,GND`
  - the ADC exposed pad uses `P,E`
- Typeboard:
  - `P,E` and `P,GND` are both used
  - `R1` bridges them
  - the repeated key-group circuitry returns locally through `P,E`
  - top-level bulk/decoupling caps return through `P,GND`
- External:
  - `P,E` and `P,GND` are both used
  - `R4` bridges them
  - active dock circuitry uses `P,E`
  - explicit local decoupling caps return to `P,GND`

## PCB Implementation Snapshot

### Common stackup

The reviewed active boards use a 4-layer, 1.2 mm stackup.

- `F.Cu`
- `In1.Cu`
- `In2.Cu`
- `B.Cu`

### Local decoupling as placed in the current PCB files

The current revision does include explicit local capacitors on all active boards.

- Controller board:
  - local USB, charger, buck, and ADC capacitors are present
- Typeboard:
  - each of the four mux groups has `100nF + 4.7uF + 10uF` on `P,+3.3`
  - additional `22uF + 22uF` top-level capacitors are also placed on `P,+3.3`
- External board:
  - `C1 = 100nF`, `C2 = 4.7uF`, `C3 = 10uF` are present on `P,+3.3`

### Footprint trend

Many of the high-value capacitors in the design use `C_0402` footprints, including `10uF` and `22uF` entries on the sub-boards.

## Controller biasing snapshot

The controller already has several explicit bias networks.

- `EN` uses `R14 = 10k` pull-up to `P,+3.3` and `C5 = 100nF` to `P,E`.
- `BOOT_1` (`GPIO8`) uses `R15 = 10k` pull-up to `P,+3.3`.
- `BOOT_0` (`GPIO9`) uses `R16 = 10k` pull-up to `P,+3.3`.
- `KEYS_CH_C` (`GPIO15`) does not have its own local bias component on the controller board.
